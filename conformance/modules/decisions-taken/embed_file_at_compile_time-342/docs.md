# Decision 342 — `@embedFile(comptime path: @Expr<string>) -> string` reads a file at compile time, in any context

The decision's file read at compile time is spelt today with `compiler.embed` (the form that replaced `@embedFile`): `compiler.embed("src/greeting.txt")`, written under `comptime` in the module's `val`, resolves the path against this package's `botopink.json`, checks the file exists, records it as an input of the build — its hash in the cache key, so a change rebuilds — and answers a `Link`; `Asset(link)` holds it. When the bytes are read is the `comptime` written at the read: the block in `main` opens the asset and reads its text at build, so `hello, embed` is a constant of the compiled program; the second read, with no `comptime`, opens the same file when the program runs. The program prints the text, the link's path `src/greeting.txt`, and `true` for the two reads agreeing. An absolute path or one leaving the package (`..`) is refused at the argument, a missing file at the call, and a path that is not known at build is `comptime-arg-not-known`; `fs` stays refused in any other comptime body.
