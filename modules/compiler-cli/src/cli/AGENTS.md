# compiler-cli/src/cli

> Path: `modules/compiler-cli/src/cli/`
> Parent: [`../AGENTS.md`](../AGENTS.md) · Root: [`../../../../AGENTS.md`](../../../../AGENTS.md)

Per-subcommand implementations and shared helpers for the `botopink` CLI.

## Tree

```text
cli/
├── AGENTS.md          ← you are here
├── build.zig          ← `botopink build`    compile project, write outputs
├── check.zig          ← `botopink check`    type-check, no code emission
├── run.zig            ← `botopink run`      build + execute entry point
├── test_cmd.zig       ← `botopink test`     compile in test mode + run test blocks
├── format_cmd.zig     ← `botopink format`   format / check .bp files
├── new.zig            ← `botopink new`      scaffold a new project
├── clean.zig          ← `botopink clean`    delete out/ + .botopinkbuild/ (+ the workspace root's .botopinkbuild/cache/ and analysis/)
├── packages.zig       ← `botopink packages --list`  the checkout's packages, one tab-separated line each (decision 993 (2))
├── packages_docs.zig  ← `botopink packages --check-docs`  the workspace documents that quote the member list, checked against the tool (decision 993 (7))
├── code_cache.zig     ← the code cache, level A (decision 509): a dependency's toolchain step by content; the closure key and std's key (level B's)
├── beam_record.zig    ← a `.beam`'s record beside it (decision 1007): which modules of `out/erlang/` / `out/beam/` a compile step compiles
├── runtime_cache.zig  ← a package's `.bpr` set and its key (decision 1006 (2), (3)): where a bare `build` writes it, when `build --target` / `run` reuse it; a by-name load's set under the loader's cache root and the loads a key covers (1006 (6) P5, 1030)
├── workspace_out.zig  ← a workspace root's one output folder per target (decision 1015 (4)): the root's `build` / `run --target` per member, the duplicate-name refusal, each dependency written once per its key
├── fanout.zig         ← the workspace fan-out (decisions 1006 (5), 1066, 1067): one process per member, one after another, the whole under `--timeout` when passed, one `ok` / `FAIL` line each with its output and the count
├── analysis_store.zig ← the code cache, level B (144 B-60): where an analysis entry lives, read whole (doubt deletes), written staged and renamed; `Cache`, the store `build` / `test` / `check` hand the comptime pass
├── unit_cache.zig     ← the unit cache (decision 1008 (2)): a dependency's emitted units per target under its `.bpr` key, taken instead of emitted; level B's CODE folded in
├── analysis_equivalence.zig ← tests only (144 B-60 S1, S2): emitting from entries read back equals emitting live, over std and the closure invariant's fixture, every target; the store in a compile — cold, writing and reading the same bytes, what is analysed and what read
├── config.zig         ← `botopink.json` loader over the shared `manifest` model: target, `entry`, `dependencies`, the enclosing workspace
├── sources.zig        ← project-source loading: drives the module tree + fallback
├── resolver.zig       ← explicit module-tree resolver (`mod`/`pub mod` → files)
├── scanner.zig        ← blind dir walk (deprecated `src/` fallback + `test/` dir, with files)
├── libs.zig           ← generic external-lib loader (`manifest.resolveDependency` over the root list → `<name>/` modules)
├── bpp.zig            ← the `.bpp` roles (decision 361): the package `"bpp"` names, its declarations std's `bpp` annotations mark
├── bpp_unfold.zig     ← the `.bpp` unfold (front 116 step 2): a `.bpp` file read as the module it spells, its lines kept; the positions a diagnostic maps back
├── arglist.zig        ← a per-module list handed to a child through a file, never its argv; the E2BIG message
├── (children)         ← every child the CLI starts (`run`, `test`, the `erl` session, `otp.job`) leads a process group of its own through compiler-core's `procgroup.zig` and is killed as a group on its end, on SIGTERM / SIGINT (`main.zig` handlers) and at exit; a workspace member's `botopink` is sent SIGTERM instead (decision 1061 (1))
├── otp.zig            ← the OTP release check of every erlang / beam run (decision 228); the command's one compile `erl` (the session); `mainEval`, the `-eval` of the VM that runs the program (`bp.otp.guardedEval`), which writes an `@panic`'s message to stderr unchanged and exits 1 on erlang and beam (144 B-41)
├── diagnostics.zig    ← shared compile diagnostics: located lex/parse/type rendering, named-set guard
└── reporter.zig       ← stdout/stderr helpers (status, errors, hints, warnings)
```

| `build.zig` | `botopink build [--target <t>] [--out <dir>] [--json] [--cache-root <dir>] [--emit-resolved <dir>] [--emit-runtime <dir>] [<file>.bpr]` | Driver — calls into compiler-core codegen. **The `.bpr` set** (decision 1006 (2)–(4), `runtime_cache.zig`): every build computes the package's key (`runtime_cache.keyOf`, the dependencies' keys filled by `libs.loadDependenciesWith` with `ClosureKeys.want_runtime`) after loading the closure and the sources; when the set in `<cache root>/.botopinkbuild/runtime/<pkg>/` (or `--emit-runtime <dir>`) is fresh and neither `Options.rebuild` (`build --cold`; `run --cold` leaves it off) nor `--emit-resolved` asks for the analysis, a bare `build` does nothing more and `build --target` emits from the root's `.bpr` (`runRuntime` with the project's own `ProjectConfig`: its code cache, no `inItsProject` refusal); else `RuntimeSink` writes the set — always, silently unless `--emit-runtime` named the directory — from the comptime pass, the key file removed first and written last, and a bare `build` stops there (`analyseOnly`: `codegen.analyse`, the build prints on stdout, each outcome rendered by `diagnostics.renderOutcome`, no OTP check). **`--json`** (decision 798 (6)): stdout is JSON lines, stderr as without it (`reporter.capture` and `manifest.capture` — a manifest's located refusal is the manifest module's to print — tee what is printed into a buffer, read back with `refusals.refusalsOf` at the end). The events, in this order: `{"event":"targets","target":<the target built>,"targets":[<the manifest's "targets", else all four>],"held":[<the targets the package holds, decision 770: `libs.heldTargets`, resolved with nothing printed>] or null when its closure does not resolve}` (after the manifest and target are read); `{"event":"build","text":<one line a build body printed>}`, one per line, in build order; `{"event":"refused","module":<module path, `main` when unlocated>,"message":<the `error…` line>,"at":<`src/<file>.bp:<line>:<col>` or null>,"label":<the caret's text or null>,"from":[<each `called from` location, innermost first>]}` (the record names of 475 (2): `refused`, `at`, `label`, `from`); `{"event":"runtime","path":<a `.bpr` written by `--emit-runtime`>,"root":<true for the root package's, the one `build <file>.bpr` takes>}`; and last `{"event":"summary","ok":<bool>,"exit":<status>,"refused":<number of refused events>}`. The raw build prints are not written to stdout in this mode. **`--cache-root <dir>`** (also `run`) sets `code_cache.root_override`: levels A and B file under `<dir>/.botopinkbuild/`, so a scratch build can share a warm cache. `--emit-resolved` / `--emit-runtime` require their directory (decision 798 (3), `main.zig` `dirValue`): missing, `=` empty or a flag in its place is `flag '…' needs a value`. `--emit-resolved <dir>` (decision 798 (2), B-163, the printer's piece) sets `comptime_pipeline.keep_resolved` and writes the resolved program one file per module of the analysed session (decision 834 (1), `codegen.Options.on_analysed`, `codegen.resolvedPrint.files`), grouped as the `.bpr` groups them — a root module at `<dir>/<package>/<module path>.bp`, a dependency's or a loaded file's at `<dir>/<pkg>/<module path>.bp`, std's at `<dir>/std/<module>.bp` —, each opened by `// module <path>`, the directories created and each file named on stderr (`tests/resolved_file.sh`); level B reads no entry under it (an entry holds no resolved program); the origins' comments are still B-163's. `--emit-runtime <dir>` (decision 805 (1), `RuntimeSink`) writes from the same hook one `<dir>/<group>.bpr` per package of the analysed program (`bp.runtime_file`: a dependency's import name, a loaded file's package, each embedded std module's path — `<dir>/std/math.bpr` —, the root package's, which alone carries the program's order and module table), the directory created, each file replaced whole (`analysis_store.write`) and named on stderr; none when a module did not analyse. Its stamp (`runtimeStamp`) is the hash of the binary's sources (`build_stamp.source_hash`). `build --target <t> <file>.bpr` (`runRuntime`, 805 (3)) reads the root's file and each package file it names from beside it and emits with `codegen.emit` — no comptime, no level B, no build output or warnings printed; `--target` is required (`runtime-target-required`), and a refused file prints `error[<code>]` (`runtime_codes`: `runtime-other-compiler` for another compiler's stamp, `runtime-unreadable`, `runtime-missing`, `runtime-not-a-program` for a dependency's file; `runtime-other-project` when the working directory's `botopink.json` is missing or names another project than the file's root, naming both — `inItsProject`, decision 838 (3), before any package file is read); the module table is the file's, the wasm host `wasi`, the `.d.ts` on commonJS as always. `tests/runtime_file.sh` pins it. **The `.comptime` stage** (decisions 1033, 1035 (1), (3), 1058 (2), (3), piece C1): `ComptimeSink`, an `AnalysedSinks` hook, so it runs with every analysis — a bare `build` and `build --target` that analyse, never one emitting from a fresh `.bpr` — and always (no switch): `bp.codegen.comptimeUnits` with the sink as its cache (`<cache root>/.botopinkbuild/cache/unit/comptime/<sha256(source stamp ‖ key)>.bpcu`, written through `analysis_store.write`; `--cold` reads none), then `write`: `<out>/wasm-comptime/<pkg>@<path>.wasm`, the core and the std units they import, each written when its bytes changed and then compiled into `<cache root>/.botopinkbuild/cache/wasmtime/<sha256>.cwasm`; a file no longer the folder's is removed and `--cold` clears the folder first. Until C4 a module the lowering refuses is recorded, not failed: `refused.txt` (`<module>\t<gap>`) and a `{"event":"comptime_refused","module":…,"gap":…}` line under `--json`, nothing on stderr. `tests/comptime_units.sh` holds it. Writes each module's build output (`GenerateResult.build_output`: what its build bodies printed, decision 788 (3)) to stdout in build order — the CLI's own messages are stderr's — unless `reporter.sink` is set (`--json`'s capture of a build). A commonJS build writes a `.d.ts` beside each `.js`, always (decision 1013 (1)). Exits 1 naming every module that produced no artifact (diagnostic rendered), writes what compiled, deletes the stale artifact of what did not. On **erlang**, `checkErlang` then compiles every `.erl` it wrote (units included) with the OTP compiler in one `erl` (`ERLANG_CHECK_EVAL`: the files read from a list file — `arglist.zig`, never one argument each — dealt round-robin to one process per scheduler, `compile:file(F, [deterministic, return_errors, {outdir, …}])` — each `.beam` beside its `.erl`, a refusal's file named by the path it was handed; a file whose `.beam` record matches is not compiled, `build --cold` compiling every one, decision 1007, `beam_record.zig`), prints each refusal as `<file>:<line>:<col>: <message>` and exits 1 on any, or when `erl` cannot be run: a build that only transpiled proved nothing about erlang (a module `erlc` rejects used to be written and exit 0). Warnings of generated code are not reported. **The code cache** (decision 509, `code_cache.zig`): a DEPENDENCY's `.erl` (`Packages.idOf`) is answered from `<cache root>/.botopinkbuild/cache/code/` when its `.beam` is there under the key of its bytes and the OTP compiler's version, else compiled `deterministic` and stored — `run` and `test` then link it instead of compiling it; the project's own `.erl` when its record does not match, a refusal every time; `--cold` reads nothing (`Options.cold`). Also owns the shared `reportUnsupportedTarget` / `reportDependencyError` / `artifactExt` helpers and the **artifact naming**: `targetSubdir` + `artifactPath` put an erlang or BEAM artifact at `<out>/erlang/<module atom><ext>` / `<out>/beam/<module atom><ext>` — flat, named by `codegen.crossModule.outputStem` over `Config.packages` (the atom starts with the package: `myapp@main.erl`, `std@math.erl`, decision 109), because `erlc` refuses a `-module` atom that differs from its file's basename and `erl -pa` wants one directory — and commonJS and its `.d.ts` are flat under the same name (`<out>/commonJS/std@math.js`, `<out>/commonJS/std@math.d.ts`, decision 1015; `outputStem`), each `require` a sibling; wasm keeps the mirrored `<out>/wasm/<module path><ext>` tree, its import segment the path. Each target's folder is named by the target, literally (decision 1023). **One `ModuleOutput` can be several files** (policy 3 of `13-module-identity`): each `GenerateResult.units` entry — a `type`'s own erlang/BEAM module — is written as `<out>/<subdir><type atom><ext>`, flat beside the file's, which is the directory `erl -pa` loads from; `removeStaleUnits` deletes them again for a module that failed this run, found by the `<module atom>@@` prefix (`crossModule.DECL_SEP`, decision 109) no other module can render. `artifactPath` takes the `Packages` too; `run.zig` passes the project's own. **`--timeout <s>`** in a package (decision 1074 (1), `armDeadline`): a watchdog thread that, at the bound, kills every child group the compiler recorded (`procgroup.killAll`: the erl session, erlc, node), names the bound and exits 1; every file of `out/<t>/`, the `.bpr` set and its key are staged and renamed (`FileWriter` through `analysis_store.write`), so a stopped build leaves the previous ones whole — the target key alone is withdrawn when the emit starts and written on success. `run` arms the same watchdog for its build and program. |

| `run.zig` | `botopink run [--target <t>] [--module <name>] [--out <dir>] [-- <args>]` (no `.bpr` path: decision 1009 — the package's own set is found by the build) | Builds into `--out` (`build --target <t>`, `<t>` the manifest's when not given: a fresh `.bpr` set is emitted from, `--cold` included, decision 1006 (4)), then runs it. On wasm it emits only the entry's component (decisions 1008 (3), 1017 (5), `Config.wasm_entry_only`: that component links every body it reaches, so no other unit is written; `build` does the same, directly or over the `.bpr`, `Options.entry` naming the module (`run --module`, default `main`) and a package with no such module keeping every unit; `failedOutputs` then takes the left-out modules as not failed; `tests/runtime_file.sh` holds it, `run` over the build's own folder answering the run's answer). A `wasi` build's component links std-wasm into the program while `build.zig`'s one switch `wasm_units` (`Config.wasm_units` of `build`, `run` and `test`) is off — off until every unit P4 emits crosses the 1037 boundary abstractly and its `botopink.units` names every unit it imports; with it on, each module is a core module written as `<pkg>@<path>.wat` / `.wasm` (its stem the last line of its `botopink.units`, decision 1032; the entry's path `wasmEntryPath`), and the build writes `std@__rt.wasm` and each std unit the entry reaches (`std@<path>.wasm`) beside it in `out/wasm/` (decisions 1021 (2), 1026, `build.zig` `writeRuntimeUnits`: the bytes of `bp.codegen.wasmRuntimeUnit`, the same for every program of one compiler build, so a file already holding them is not written again). A matching target key (decision 1008 (1), `runtime_cache.zig`) and the entry's artifact present: `run` emits and compiles nothing, it executes. commonJS spawns `node` on `build.artifactPath(…)`; a `wasi` wasm build — a WASI preview 2 component (decision 334: `build` sets `Config.wasm_artifact`, `wat_emitter.renderComponent`) — runs in this process (`runWasi`, decisions 1032 (3), 1034: compiler-core's `codegen/wat/runner.zig`, no `wasmtime` CLI): a units entry (a core module carrying `botopink.units`) composed by `wasmRunner.runEntry` with the unit files beside it (R2: each unit and the frame one `.cwasm`, compiled once for every program reaching it), any other component compiled through `<cache root>/.botopinkbuild/cache/wasmtime/<sha256>.cwasm` (`--cold` reads none and writes what it compiled; nothing under `~/.cache/wasmtime`, decision 1008 (5)), given the host services its `botopink.needs` names (`http` → `wasi:http` and the network, `filesystem` → `/` and the working directory), argv, env and stdin inherited, the program's exit status passed through, a trap printing its `wasm trap: …` line on stderr and exiting 1, Ctrl+C ending it with 130 (decision 878, `main.zig`'s SIGINT handler calls `wasmRunner.interrupt`; also `test_cmd.zig`'s runs); a `browser` build (`"wasm": { "host": "browser" }`) is `node <module>.mjs`, the loader `build`'s `writeOutputs` writes beside `<module>.wasm` (`bp.codegen.wasmBrowserLoader`). **erlang** is two steps, not one (`erlangArgv`): what `erlc -o <out>/erlang` over every emitted `.erl` found recursively does — run as one `erl` that reads the files from a list file (`compileAll`, `COMPILE_EVAL`: `compile:file(F, [report, {outdir, Dir}])`, `from_asm` added on beam), because `erlc` takes its files on the command line only — then `erl -noshell -pa <out>/erlang -eval "<entry atom>:main([]), halt()."` — the entry atom starts with the project's package (`myapp@main`, decision 109), which the `-eval` used to spell as the bare module path — `escript` compiles only the file it is handed, so every cross-module call was `undef` at run time, and `main([])` is used because `main/0` is emitted only when `main` is `pub`. A crashing erlang program exits `1` (`erl`'s status) where `escript` exited `127`. **beam** is the same two steps (`beamArgv`): `erlc +from_asm -o <out>/beam` over every emitted `.S` (the same list-file `erl`) — the `.beam`s land BESIDE the `.S` files, which is the directory the build ships a host `.erl` into and the one the entry's `'__bp_load_siblings'/0` reads — then `erl -noshell -pa <out>/beam -eval "'<entry atom>':main([]), halt()."`. Nothing here compiles a sidecar: the assembled program does, so it runs the same way outside this command. It used to write the `.S` and print an `erlc +from_asm` hint, exit 0. `programArgv` is the command line of the built program (the erlang / BEAM compile step first, a refusal printed `the OTP compiler refused the emitted program`); `run` appends the program's arguments and spawns it with inherited stdio, `cell check` spawns it captured. **`--timeout <s>`** (decision 1067) bounds the whole command when passed, the build included: a `wasi` program is handed the time left as the runner's epoch deadline (`WasiRun.timeout_ns`, `WasiRan.timed_out`); a spawned program (`spawnWaitUntil`, its own group, decision 1061 (1)) is killed as a group when the time runs out; the command then exits 1 naming the bound. |
| `test_cmd.zig` | `botopink test [--target <t>] [--filter <substr>] [--json]` | Compiles with `test_mode = true` — every module's production unit is the one `build` writes, and each module of the package under test that declares tests gets its test unit (`GenerateResult.test_unit`, decision 513: its tests, registry and runner; `testUnitPath` places it — `__test__/<pkg>@<path>.js` (decision 1015), `'__test__@<pkg>@<mod>'.erl` beside its module, `.S` in the run's directory, `__test__/<path>.wat`) —, writes to `.botopinkbuild/test-out/<target>/<id>/` (one directory per run and per target — `id` is 64 random bits, the shape `codegen/runtime.zig`'s `makeScratchDir` uses — removed when the run ends), runs each test unit via `node` (commonJS), `escript` (erlang), the in-process runner (`run.runWasi`; wasm, the `wasi` host; stdout captured under `--json`, else streamed and kept for the summary; a `browser` host is refused; with `build.wasm_units` on, each module's unit `<stem>.wasm` and its test entry `<pkg>@<module>.test.wasm` (`wasmTestEntry`) are written in the run's folder and composed from there, the core and std's units the compiler's own bytes) or `erl` (beam: every module and unit is `<atom>.S` flat in the run's directory — `artifactIn` — the host `.erl`s shipped beside them, all assembled once by `assembleBeam`, `erlc +from_asm`, whose refusal fails the run; then `erl -noshell -pa <dir> -eval "'<atom>':main(init:get_plain_arguments()), halt()." -extra [filter]`) with `BOTOPINK_TEST_TMPDIR` (`TEST_TMPDIR_ENV`, `testTmpEnv`) naming the run's own absolute `<run dir>.tmp` (`testTmpDir`) — the one place a test writes files, since the two cells of one library share its directory as cwd (rakun's fixture projects under `.botopinkbuild/tmp/` made its commonJS pins read 6, `build`, 1 on three gates); it is the run directory's sibling, never inside it, because each erlang runner compiles and loads every `.erl` under its own directory, and rakun's fixture builds left ~6 500 there. On erlang, once every `.erl` of the run (sidecars included) is written, `precompileErlang` compiles each ONCE in one `erl` — a process per file, the loader's own options — and writes `<name>.beam` beside every source that compiled; each runner's `__bp_load_siblings` loads those and compiles from source only a module with no `.beam` (one that does not compile, or a source with `-include`), so a dead sibling is refused with the same message as before. Measured on `libs/std` (24 test modules, 32 modules): the erlang cell went from ~24.6 s to ~10.3 s, all of it the T × M `compile:file/2` calls this removes. **The code cache** (decision 509, `code_cache.zig`): every module and `type` unit of another package than the one under test is linked beside its source from `<cache root>/.botopinkbuild/cache/code/` when its `.beam` is there, else compiled `deterministic` and stored; the modules under test are compiled every time; on beam, `assembleBeam` assembles the run's `.S` through `run.compileInto`, the same store for a dependency's `.S`; `--cold` reads nothing. **Level B** (`analysis_store.zig`, 144 B-60): a dependency's analysis is read from its entry as `build` reads it, and its units from the unit cache (`unit_cache.zig`, decision 1008 (2)) — a dependency has no test unit and its production unit does not depend on `test_mode` (decision 513); a test unit is never cached and the package under test is never stored. A module that fails to compile is rendered and named and fails the run (exit 1), but does not stop the modules that compiled from running their tests; the run's own directory is new, so no previous artifact is in it and no concurrent run can empty it — two gates over one library checkout (`botopink-lib-test` gives each cell `cwd = <lib dir>`) used to wipe each other's artifacts and produce a library red owned by nobody. `--json` re-emits the test envelope as JSONL (`emitJsonl` + `parseFailLine` + `parseDurationMs`; schema in [`../../AGENTS.md`](../../AGENTS.md)) and aggregates one `{"event":"summary",…}` across every module. **Text mode has one summary PER MODULE** — each child runner prints its own `<P> passed, <F> failed` — so the last line of a multi-module run used to be the last MODULE's count and not the run's; two fronts of 1.0.10-beta nearly took it for a suite baseline. Text mode therefore labels each one with a `----- TESTS OF <module> -----` banner, streams each child's stdout through (`teeModuleStdout`, live) while reading its summary line (`parseSummaryLine`), and ends the run with its **total** as the last stdout line: `total: <P> passed, <F> failed in <N> module(s)` (`TOTAL_PREFIX`) — the line `botopink-lib-test` reads a text-mode cell's count from. A module whose runner printed no summary line (it stopped before its tests finished, and its tests are in no count) is named and fails the run, in both modes. Neither the banner nor the total is printed under `--json`, whose stdout channel stays pure JSONL and aggregates one `{"event":"summary",…}`. **A stale binary is refused first**: `run` calls `source_stamp.checkFresh` over the checkout the binary was built from (`build_stamp`, embedded by `build.zig`) and exits 1 naming it when its sources changed since — a library run against a stale compiler measures the previous compiler ([`../../../source-stamp/AGENTS.md`](../../../source-stamp/AGENTS.md)). Loads declared `dependencies` so a consumer's tests can `import … from "<lib>"`; a dependency's own `test {}` blocks are NOT run. Bare imports (`import {x};`) resolve to a root `module.js` aggregator merging every src/dep module's exports; **`test/` suite modules are excluded** from it — they export nothing others consume, and cross-loading one (which may run module-load side effects like decorator `@emit`s) from another test's run would hit a half-built aggregator and crash. Every commonJS module sits beside the aggregator in the run's one flat folder as `<pkg>@<path>.js` (`artifactIn`, decision 1015), so a bare-import `require("./module")` resolves from any of them. A dependency's declaration (`.d.bp`) modules are kept, as `build`, `run` and `check` keep them (decisions 514, 515): one module set under every command, one level B entry. A child that exits non-zero — a failing test, or a module that did not load (a `SyntaxError`, an `erlc` refusal) — gets a `----- <module> EXITED WITH STATUS <n> -----` line, and the text report ends with a `----- <N> MODULE(S) RAN, <K> EXITED NON-ZERO -----` footer right before the total; under `--json` a runner whose summary never came emits `{"event":"module_crashed","module":…,"exit":…}` and counts as one failure. |

## Conventions

- **The std tree and the import grammar** (decisions 106, 107, 110): std is a
  pure root of modules with two folders, `io/` and `testing/`
  (`libs/std/AGENTS.md`); an import item is a dotted path whose **leaf** alone
  enters scope, braces group items under a node, `as` renames a leaf and `*`
  activates one (`compiler-core/src/parser/AGENTS.md`, `comptime/AGENTS.md`).
  The CLI meets it where it resolves imports: `resolver.zig` checks that a
  `from` names a package and that a brace path names a module of the package
  (`conformance/docs.md` § Imports).

- Project `src/` is loaded through `sources.zig` (explicit module tree); the flat
  `test/` suite dir keeps the deterministic `scanner.zig` walk (sort by path).
- Every loader fills `Module.srcPath` — the package-root-relative path with its
  extension and forward slashes, which is what `@src().file` answers (1.0.10-beta
  decision 73): `resolver.zig` uses the file it read (`src/shapes/circle.bp`),
  `scanner.zig` the scan dir plus the entry (`test/color_test.bp`), `libs.zig`
  `<manifest.src>/<file>` relative to the dependency's own root. It is gpa-owned
  like `path`/`source`; every `freeModules`/`free` releases it.
- Every module carries the reader `@embed` reads its package through
  (`Module.files = bp.PackageFiles.disk(io, <package dir>)`, decision 519):
  `sources.zig` hands the project's modules `proj.dir`, `test_cmd.zig` and
  `check.zig` the `test/` modules the same, and `libs.zig` `loadOne` a
  dependency's modules its directory — gpa-owned there, released with the
  module wherever `srcPath` is.
- Errors, warnings, and hints go through `reporter.zig` so output style stays
  consistent (`error: …` / `warning: …` / `hint: …`).

## Scratch paths in tests

A unit test in this package that writes to disk takes its path from the
`test_scratch` module — `test_scratch.path(io, "<case>/…")`,
`test_scratch.remove(io, "<case>")` — never a hand-spelled
`.botopinkbuild/<case>` (`scripts/check-test-scratch.sh` refuses that, decision 67, no flag).
The test cwd is this package's directory, shared by every process running the
suite; a per-case-but-not-per-run path let a second `zig build test` empty the
first one's fixtures mid-test. See
[../../../test-scratch/AGENTS.md](../../../test-scratch/AGENTS.md).
