# compiler-cli/src/cli

> Path: `modules/compiler-cli/src/cli/`
> Parent: [`../AGENTS.md`](../AGENTS.md) · Root: [`../../../../AGENTS.md`](../../../../AGENTS.md)

Per-subcommand implementations and shared helpers for the `botopink` CLI.

## Tree

```text
cli/
├── AGENTS.md          ← you are here
├── build.zig          ← `botopink build`    compile project, write outputs
├── check.zig          ← `botopink check`    type-check, no code emission
├── run.zig            ← `botopink run`      build + execute entry point
├── test_cmd.zig       ← `botopink test`     compile in test mode + run test blocks
├── format_cmd.zig     ← `botopink format`   format / check .bp files
├── new.zig            ← `botopink new`      scaffold a new project
├── clean.zig          ← `botopink clean`    delete out/ + .botopinkbuild/
├── migrate.zig        ← `botopink migrate`  generate the mod tree from src/ layout
├── migrate_effects.zig ← `botopink migrate effects`  the front-24 effect codemod
├── config.zig         ← `botopink.json` loader over the shared `manifest` model: target, `entry`, `dependencies`, the enclosing workspace
├── sources.zig        ← project-source loading: drives the module tree + fallback
├── resolver.zig       ← explicit module-tree resolver (`mod`/`pub mod` → files)
├── scanner.zig        ← blind dir walk (deprecated `src/` fallback + `test/` dir, with files)
├── libs.zig           ← generic external-lib loader (`manifest.resolveDependency` over the root list → `<name>/` modules)
├── diagnostics.zig    ← shared compile diagnostics: located lex/parse/type rendering, named-set guard
└── reporter.zig       ← stdout/stderr helpers (status, errors, hints, warnings)
```

## Subcommands

| File | Command | Notes |
|---|---|---|
| `build.zig` | `botopink build [--target <t>] [--out <dir>] [--typescript]` | Driver — calls into compiler-core codegen. Exits 1 naming every module that produced no artifact (diagnostic rendered), writes what compiled, deletes the stale artifact of what did not. Also owns the shared `reportUnsupportedTarget` / `reportDependencyError` / `artifactExt` helpers and the **artifact naming**: `targetSubdir` + `artifactPath` put an erlang or BEAM artifact at `<out>/erl/<module atom><ext>` / `<out>/beam/<module atom><ext>` — flat, named by `codegen.crossModule.outputStem` over `Config.packages` (the atom starts with the package: `myapp@main.erl`, `std@math.erl`, decision 109), because `erlc` refuses a `-module` atom that differs from its file's basename and `erl -pa` wants one directory — while commonJS, its `.d.ts` and wasm keep the mirrored `<out>/<module path><ext>` tree, whose `require` target and wasm import segment ARE the path. **One `ModuleOutput` can be several files** (policy 3 of `13-module-identity`): each `GenerateResult.units` entry — a `type`'s own erlang/BEAM module — is written as `<out>/<subdir><type atom><ext>`, flat beside the file's, which is the directory `erl -pa` loads from; `removeStaleUnits` deletes them again for a module that failed this run, found by the `<module atom>@@` prefix (`crossModule.DECL_SEP`, decision 109) no other module can render. `artifactPath` takes the `Packages` too; `run.zig` passes the project's own. |
| `check.zig` | `botopink check [<path>]` | Same pipeline as `build`, stops after type inference. Loads the set `test` compiles — `src/` **and** `test/` — plus declared `dependencies`; `<path>` changes into that project first. |
| `run.zig` | `botopink run [--target <t>] [--module <name>] [--out <dir>] [-- <args>]` | Builds into `--out`, then runs it. commonJS and wasm spawn `node` / `wasmtime` on `build.artifactPath(…)`. **erlang** is two steps, not one (`runErlang`): `erlc -o <out>/erl` over every emitted `.erl` found recursively, then `erl -noshell -pa <out>/erl -eval "<entry atom>:main([]), halt()."` — the entry atom starts with the project's package (`myapp@main`, decision 109), which the `-eval` used to spell as the bare module path — `escript` compiles only the file it is handed, so every cross-module call was `undef` at run time, and `main([])` is used because `main/0` is emitted only when `main` is `pub`. A crashing erlang program exits `1` (`erl`'s status) where `escript` exited `127`. `beam` only writes the `.S` artifact and prints the `erlc +from_asm` hint. |
| `test_cmd.zig` | `botopink test [--target <t>] [--filter <substr>] [--json]` | Compiles with `test_mode = true` (test blocks emit as a registry + runner; `main/0` not auto-invoked), writes to `.botopinkbuild/test-out/<target>/<id>/` (one directory per run and per target — `id` is 64 random bits, the shape `codegen/runtime.zig`'s `makeScratchDir` uses — removed when the run ends), runs each test-containing module via `node` (commonJS) or `escript` (erlang); other targets are rejected. On erlang, once every `.erl` of the run (sidecars included) is written, `precompileErlang` compiles each ONCE in one `erl` — a process per file, the loader's own options — and writes `<name>.beam` beside every source that compiled; each runner's `__bp_load_siblings` loads those and compiles from source only a module with no `.beam` (one that does not compile, or a source with `-include`), so a dead sibling is refused with the same message as before. Measured on `libs/std` (24 test modules, 32 modules): the erlang cell went from ~24.6 s to ~10.3 s, all of it the T × M `compile:file/2` calls this removes. A module that fails to compile is rendered and named and fails the run (exit 1), but does not stop the modules that compiled from running their tests; the run's own directory is new, so no previous artifact is in it and no concurrent run can empty it — two gates over one library checkout (`botopink-lib-test` gives each cell `cwd = <lib dir>`) used to wipe each other's artifacts and produce a library red owned by nobody. `--json` re-emits the test envelope as JSONL (`emitJsonl` + `parseFailLine` + `parseDurationMs`; schema in [`../../AGENTS.md`](../../AGENTS.md)) and aggregates one `{"event":"summary",…}` across every module. **Text mode has one summary PER MODULE** — each child runner prints its own `<P> passed, <F> failed` — so the last line of a multi-module run is the last MODULE's count and not the run's; two fronts of 1.0.10-beta nearly took it for a suite baseline. Text mode therefore labels each one: a `----- TESTS OF <module> -----` banner before every child and a `----- <N> MODULE(S) RAN — each "N passed, M failed" above is that module's own -----` footer at the end. Neither is printed under `--json`, whose stdout channel stays pure JSONL. Loads declared `dependencies` so a consumer's tests can `import … from "<lib>"`; a dependency's own `test {}` blocks are NOT run. Bare imports (`import {x};`) resolve to a root `module.js` aggregator merging every src/dep module's exports; **`test/` suite modules are excluded** from it — they export nothing others consume, and cross-loading one (which may run module-load side effects like decorator `@emit`s) from another test's run would hit a half-built aggregator and crash. For nested dep module names (`<lib>/<module>`), a per-directory `module.js` shim re-exports the root aggregator so their bare-import `require("./module")` resolves. `check`/`test` skip declaration-only (`.d.bp`) dep modules. |
| `format_cmd.zig` | `botopink format [--check] [paths...]` (alias `fmt`) | Round-trip stable formatting. No argument: `collectTree` walks the current directory whole — every `.bp` and `.d.bp` under `src/`, `test/`, `examples/` and the projects nested inside (decision 66). A directory argument is walked the same way, a file argument is taken as is. The walk does not enter a hidden directory or `node_modules`, and does not reach `reject/<n>.bp` when `<n>.expect` sits beside it — the language suite's rejected program, recognised by the directory's name and the pair, at any depth (decision 67: structural, never a skip list, a pragma or an environment variable; this file must not grow one). A file that does not lex or parse is rendered with its location and counted as an error in both modes (exit 1). |
| `new.zig` | `botopink new <name> [--target <t>]` | Drops a project template. A name `manifest.nameRefusal` refuses (not starting with a lowercase letter, or `bp` — decision 109) is refused before anything is scaffolded. The template **prints** (`@print(greet("world"))`): a block's value is its `break` (semantics decision 2), so a body whose only statement is a string literal evaluates to nothing and `botopink run` shows an empty screen. `tests/cli_contract.sh` pins both the `@print` and the run output. |
| `clean.zig` | `botopink clean` | Removes `out/` and `.botopinkbuild/`; prints `Removed` only on success and exits 1 when a delete fails. |
| `migrate.zig` | `botopink migrate [--dry-run]` | Derives the explicit module tree from the current `src/` layout — prepends `pub mod X;` to each directory's index (`root.bp`/`main.bp` at the root, `mod.bp` per folder), creating index files as needed. Idempotent; defaults to `pub mod` to preserve the reachability the implicit scan gave. |
| `migrate_effects.zig` | `botopink migrate effects [--dry-run]` | The codemod of front 24 (1.0.10-beta, decisions 118–128): today's effect surface → `guide.md`'s. The subcommand word comes first (`migrate --dry-run effects` is a usage error), so `migrate` alone keeps its module-tree meaning (`decisions-pending.md`, front 24 open point 7). Runs in a package (not a workspace umbrella) over every `.bp`/`.d.bp` under `src/` and `test/`; dependencies are read for context bases and types, never rewritten. **Three stages per file**, each a list of byte-range edits (`Editor`), so comments and layout survive: `stage1` normalises the pre-121 spellings to today's language (`#[@context]`→`#[@use]`, `#[@iterator]`→`#[@resultGenerator]`, `#[@asyncGenerator]`→`#[@futureGenerator]`, `@Context<B, R>`/`@Use<C, T>`→`@Component<C, T>`, `@Component<T>`→`@Component<B, T>` and a hook-using `-> T`→`#[@use] … -> @Component<B, T>` with `B` read off `type T … implement @Context<B>` in every loaded source (`collectBases`), `@Iterator<T, E>`→`@ResultGenerator`, `@AsyncIterator`→`@FutureGenerator`, `IteratorStep`→`YieldStep`, `loop (xs) { x -> }`→`for`, `loop (cond)`→`while`, `loop await`→`for await`); every project module, normalised, is type-checked once (`compileTypesOnly`) — in the order the loaders hand the modules over (`planInputs`: `sources.load`'s module tree, where an imported module precedes its importer, then `test/`, then the files nothing compiles; each keeps its `declaration` flag), never the files sorted by path, which put rakun's `config.bp` ahead of the `runtime.bp` it imports and left the whole package unchecked — with `comptime_pipeline.ExprTypeLog` installed — the type of each expression by file and location; `stage2` removes the six annotations (the line when alone on it, else the item), renames the wrappers (`rewriteType`: `@Future<T, E>`→`@Task<@Result<T, E>>`, `@Future<T>`→`@Task<T>`, `@Generator`→`@Iterator`, `@ResultGenerator<T, E>`→`@Iterator<@Result<T, E>>`, `@FutureGenerator<T, E>`→`@Stream<@Result<T, E>>`, `YieldStep<T, E>`→`YieldStep<T>` — nested, `>>`-split and arity-checked), prefixes annotated loops (`iter` / `stream`, and `#[@X] loop { for (xs) {…}; break; }`→`iter for (xs) {…}`), and — from the types (`semantic`) — writes `try await x` where the awaited `@Future<U, E>` has a concrete `E` and the new return has a `@Result` layer (`hasResultLayer`), and `(try r)` at the one use of the item of a `for` / `for await` over a fallible generator. Every site it cannot decide gets a `// TODO(migrate-effects): <why>` line above it (`Editor.mark`, which reads the marker block already there, so a re-run adds nothing): `await` / `throw` / `try` with no `@Result` left to propagate into (hooks and components), a `@Future<T>` body that throws or tries (open point 5), a `for` item used other than once, `case` over `YieldStep` with an `Error` arm, `.next()` on a fallible generator, an effect behind a named return (an alias), a `pub` fallible `@Future` (JS callers no longer see a rejection), a `declare fn … -> @Future<T>` (a host rejection turns fatal), a `.returnType` compared with a renamed wrapper's head (`decl.returnType != "Future"` in a decorator refuses every function the migration rewrote; `markReturnTypeNames`, syntactic), `Iterable`, `Yield<T, R>`, an arity no row covers. **Idempotent:** a file the syntactic passes leave unchanged is not analysed (the migrated language does not type-check with today's compiler). A module that does not type-check is rendered and its `await` / `for await` sites marked — never guessed (decision 67); exit 0. Snapshots: `snapshots/cli/migrate_effects_{all,review}_patterns.snap.md`. **Merge hazard:** stage 2 relies on today's parser and checker accepting the old surface; once front 24's E2 refuses it, the codemod needs that parser's recognise-and-refuse path to still build an AST, or runs from a pre-E2 binary. |

## Shared helpers

| File | Role |
|---|---|
| `config.zig` | Loads `botopink.json` through the shared `manifest` model (`modules/manifest`; schema `docs/botopink-json.md`) into `ProjectConfig` (`name`, `version`, `target` — `commonJS` when unset —, `entry` module-tree root, `dependencies`, `files`, the full `manifest`, the absolute `dir`, and `workspace`: the enclosing workspace when the project is a member). `files` is the package's declared surface — the modules it ships outside its own `mod` tree, each relative to `src`. `dependencies` is the object form only (decision 76): `{ "<name>": { "path" } \| { "git", "branch"\|"tag"\|"rev" } \| { "workspace": true } }` → `[]DepEntry` (`DepEntry`/`DepSpec`/`DepRef` are the shared types). Every refusal — not JSON, the retired string array (the message names the rewrite), an entry without a source or with two, two pins, a workspace manifest where a package is needed (`… is a workspace, not a package — run this command inside one of its members: a, b`) — is printed located by `load`/`parse` before `ConfigInvalid`; `parseLocated` hands it back for tests. |
| `sources.zig` | Loads a package's project modules: resolves the explicit module tree (`resolver.zig`), warns on orphaned `.bp`, and falls back to the deprecated blind scan when a package has no `main.bp`/`root.bp` root. Every command loads `src/` through here, so the resolver's checks (including the unresolved-import-source one) apply to `build`, `check` and `test` alike. It passes `proj.dependencyNames` as the resolver's `externals` and renders each `resolver.Diagnostic`, appending an `at: <file>:<line>:<col>` line when one is located. `checkFlatImports` applies the same import-source rule to a directory the resolver never sees — the flat `test/` suite — by handing `resolver.checkSources` the package's resolved modules together with the flat ones, so a `*_test.bp` may import the package it tests and still cannot name a module that does not exist. |
| `resolver.zig` | Builds the package's module set by following `mod`/`pub mod` from the root (`main.bp` binary / `root.bp` library, per `entry`). `mod Name;` resolves `Name.bp` or `Name/mod.bp` (exactly one); both/neither errors. Reports orphans — a `.bp` under `src/` that **neither** a `mod` path **nor** the manifest's `files` reaches, since those are the two routes a module has into a build — enforces path-visibility (an import may cross into a module only if every `mod` on its path is `pub mod` — a private `mod` is reachable only within its declaring module's subtree), checks that `import … from "a.b"` naming a package module actually exports the symbol (dotted = `mod` chain) — and, since the `externals` argument (`sources.zig` passes the project's `dependencies`), that the `from` names **something**: a package module, a declared dependency (`<dep>` or `<dep>.<module>`) or `std`, else `UnresolvedImportSource`. Both diagnostics carry `file:line:col`, read off the `from "…"` string token (`fromLocations` — `ast.ImportDecl` has no `Loc`). Finally it topologically orders modules so an imported module compiles before its importer. **The edge is drawn from the module an import NAMES** (`importOwner`), not from `Analysis.owner`, which maps a bare symbol to the FIRST module exporting it over the whole package — a name is unique inside a module and never over a program (`libs/std` declares `parse` in `json`, in `querystring` and in `url`). Two modules exporting one name drew the edge to the wrong one and the module actually imported got none at all: it sorted AFTER its own importer, was missing from the comptime registry when that importer resolved its imports, and the importer was type-checked against the other module's declaration. Measured: `import {parse} from "two"` with a `one` that also declares `parse` was refused on all four backends with `one`'s arity — "'parse' expects 1 argument(s), got 2". `Analysis.owner` still answers when the `from` names no project module (a dependency handle, `std`, a bare `import { … };`). `checkSources` exposes the import-source check alone, for a module set that is not a package (`sources.checkFlatImports`). |
| `scanner.zig` | Blind directory walk (every `.bp` becomes a module), sorted by path. Deprecated fallback for `src/` when no module-tree root exists; still the loader for the flat `test/` suite dir, which is not a package. `scanSourcesWithFiles` returns a `Scan` — the modules plus, aligned by index, the path each was read from — because a directory that never reaches the resolver still has to locate its own diagnostics; `scanSources` is that minus the files. |
| `libs.zig` | Resolves `dependencies` (`[]DepEntry`) to `<name>/` modules on disk (lib-agnostic — the core sees ordinary `Module[]` prefixed `<name>/`). `packagesOf(proj, dep_modules)` is the compilation's `crossModule.Packages` — the project's `name` and the first segment of every loaded dependency module — which `build` and `test` hand to `Config.packages`, so every erlang/BEAM atom starts with its package (decision 109). `loadDependencies(proj)` scans `resolveLibRoots` (`BOTOPINK_LIB_ROOTS` entries, then the walk-up roots: an ancestor holding a workspace manifest, `D/repository/botopink-lang/libs`, `D/repository`, `D/libs`) and `resolveFallbackRoots` (`<project>/.botopinkbuild/deps/`, the symlink store written by `bpmp install`) with `manifest.scanRoots` (packages and workspace members alike) and resolves each entry with `manifest.resolveDependency` — `path` from the project directory, `workspace` from the enclosing workspace, `git` by name; a refusal (a workspace by name, a `path` to a sibling member, a name two members declare, …) is printed located → `LibManifestInvalid`; nothing carrying the name → `LibNotFound`; no root at all is not an error (`path`/`workspace` need none); a `files` entry that cannot be read → `LibFileNotFound`, after `renderMissingFile` prints the path and the manifest entry's location. `resolveBpmpStoreRoot` computes `$BPMP_HOME/store/` (else `$XDG_CACHE_HOME/bpmp/store/`, else `$HOME/.cache/bpmp/store/`) but is not yet consulted by the loader. `shipMjsSidecars` copies a lib's `.mjs` sidecars next to the emitted JS. The owner of a sidecar is the dependency the build **resolved**, not an entry of that name across the roots: `sidecarOwner` re-runs `manifest.resolveDependency` over the project's own manifest (`ProjectManifest`, read once, parsed under the bare `botopink.json` so a refusal locates like every other CLI diagnostic) and reads the file under that package's own `src` — `<src>/sidecars/<base>`, then `<src>/<base>`. Asking the roots by name is a different question with a different answer: a `path` dependency outside every root has no entry, and a name two checkouts declare is a located problem rather than a directory — both used to end in a silent `null` and exit 0. Only an owner the project does not declare (the embedded `std`, emitted as `std/<mod>`) falls back to `manifest.find` across the roots. A sidecar a module requires and the build cannot ship is a located refusal (`refuseSidecar`, located by `sidecarLocation` on the `dependencies` entry that named the library, else on the `"src"` of the manifest it was looked for under) that is `error.SidecarRefused` once the diagnostic is printed; `build.zig` and `test_cmd.zig` propagate it and answer exit 1 (both used to call the shipper as `… catch {}`, which is why the refusal once had to `std.process.exit(1)` by hand); no flag, env var or manifest field turns it off (decision 67). `shipErlSidecars` is its erlang counterpart — it shares `sidecarOwner` but not the refusal: an unresolved qualifier there is an OTP module, not a sidecar the library named — it reads the `atom:atom(` qualifiers out of the emitted erlang (`QualifierIterator`) and copies the host `<atom>.erl` a lib keeps in `src/sidecars/` or `src/` into the output, so `#[@External.Erlang("host", "fn")]` resolves. It asks `sidecarOwner` once per library and probes each (owner, qualifier) pair once per run — both answers depend only on the roots and the project's manifest — because an OTP qualifier (`lists:`, `maps:`) is never a sidecar and used to re-scan every library root at every occurrence (emilia's `emilia-backgrounds`, 1 849 emitted modules: ~51 s → ~11 s on erlang). Called by `test_cmd.zig`; the `build.zig` call site is still open (that output has no sibling loader). |
| `diagnostics.zig` | Shared by `build`/`check`/`test`: `renderOutcome` renders the diagnostic a comptime outcome carries — `printSyntaxError` for a lex/parse error (`ComptimeOutput.Outcome.parseError`'s `SyntaxError`), the type or validation error otherwise — with file, line and excerpt; `failedOutputs` renders the diagnostic every failed `codegen.generateWith` entry carries (`renderResult`) and names the failed non-declaration modules; `reportFailedModules` / `reportOrphans` print the summary lines. `printLexError` / `printParseError` are reused by `format`. |
| `reporter.zig` | Single source of truth for CLI text — `reporter.errMsg`, `warnMsg`, `warnDetail`, `hintMsg`, `stdout`, plus status lines (`compiling`, `compiled`, `checking`, `checked`, `formatChanged`, …). |

## Conventions

- Project `src/` is loaded through `sources.zig` (explicit module tree); the flat
  `test/` suite dir keeps the deterministic `scanner.zig` walk (sort by path).
- Every loader fills `Module.srcPath` — the package-root-relative path with its
  extension and forward slashes, which is what `@src().file` answers (1.0.10-beta
  decision 73): `resolver.zig` uses the file it read (`src/shapes/circle.bp`),
  `scanner.zig` the scan dir plus the entry (`test/color_test.bp`), `libs.zig`
  `<manifest.src>/<file>` relative to the dependency's own root. It is gpa-owned
  like `path`/`source`; every `freeModules`/`free` releases it.
- Errors, warnings, and hints go through `reporter.zig` so output style stays
  consistent (`error: …` / `warning: …` / `hint: …`).

## Scratch paths in tests

A unit test in this package that writes to disk takes its path from the
`test_scratch` module — `test_scratch.path(io, "<case>/…")`,
`test_scratch.remove(io, "<case>")` — never a hand-spelled
`.botopinkbuild/<case>` (`scripts/check-test-scratch.sh` refuses that, decision 67, no flag).
The test cwd is this package's directory, shared by every process running the
suite; a per-case-but-not-per-run path let a second `zig build test` empty the
first one's fixtures mid-test. See
[../../../test-scratch/AGENTS.md](../../../test-scratch/AGENTS.md).
