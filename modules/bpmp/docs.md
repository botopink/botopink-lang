# bpmp — end-user tutorial

bpmp is the package manager and toolchain manager for botopink. One CLI,
two files, one disk layout. This page is for users who want to *use* bpmp,
not contribute to it; the implementation lives in
[AGENTS.md](AGENTS.md) and the specs in `tasks/v0.beta.18/specs/`.

## Install

```bash
# POSIX
curl --proto '=https' --tlsv1.2 -sSf https://botopink.dev/install.sh | sh

# Windows (PowerShell)
iwr https://botopink.dev/install.ps1 -useb | iex
```

Each installer downloads the latest release, verifies its sha256 sidecar,
and lays out `$BPMP_HOME` (default `~/.bpmp/`). It prints a one-line
`export PATH=…` snippet at the end; running `bpmp env` will print the same
snippet later if you forget.

Manual install: grab a tarball from the
[Releases page](https://github.com/botopink/botopink-lang/releases),
verify the sha256, and put `bpmp` on your `PATH`.

## Layout of `$BPMP_HOME`

```text
$BPMP_HOME/
├── bin/bpmp                                   # shim
├── botopink/versions/<ver>/{botopink,botopink-lsp,botopink-lib-test,bpmp}
├── botopink/versions/stable -> <ver>          # symlink (junction on Windows)
├── packages/<name>/versions/<ver>/{botopink.json,src/…}
└── cache/                                     # content-addressed tarballs
```

## The two project files

Every botopink project carries:

```text
botopink.json         compiler + bpmp manifest (you hand-edit + bpmp writes)
botopink.lock.json    bpmp's commit-pinned source of truth (don't hand-edit)
```

`botopink.json` shape (full schema in [`docs/botopink-json.md`](../../docs/botopink-json.md)):

```jsonc
{
  "name":         "myapp",
  "version":      "0.1.0",
  "target":       "commonJS",
  "entry":        "src/main.bp",
  "src":          "src/",
  "dependencies": ["erika"],          // compiler reads
  "botopink":     ">=0.0.1",          // bpmp reads (min compiler tag)
  "requires":     { "erika": "^0.0.1" } // bpmp reads (per-dep constraint)
}
```

`botopink.lock.json` is generated by bpmp — commit-pinned so a teammate's
`bpmp install` resolves the same tree even if a moving feat tag has shifted.

## Tutorial — your first project

```bash
$ mkdir my-app && cd my-app
$ bpmp init --target commonJS --name my-app
bpmp init: wrote botopink.json + botopink.lock.json
next steps:
  • run `bpmp install <name>` to add a framework
  • run `bpmp run -- build src/main.bp` to compile

$ bpmp install erika@^0.0.1
bpmp install: added erika (^0.0.1) to botopink.json (dependencies + requires)
hint: re-run `bpmp install` once the network resolver lands to pin the commit.

$ bpmp list
Project
  name:    my-app
  version: 0.0.1

Dependencies (1)
  • erika           ^0.0.1

Lockfile (0 pinned)

$ bpmp run -- build src/main.bp
# (spawns active botopink with BOTOPINK_LIB_ROOTS = ~/.bpmp/packages/erika/versions/<v>)
```

## Locked reinstall on another machine

```bash
$ git clone repo && cd repo
$ bpmp install                # no args → replay botopink.lock.json
installing 3 package(s) from botopink.lock.json
  ✓ erika 0.0.1 (already installed at ~/.bpmp/packages/erika/versions/0.0.1)
  ✓ jhonstart 0.1.2 (already installed at …)
  ✓ rakun 0.0.4 (already installed at …)
```

A cold cache walks each package through download → sha256 verify → extract
under `$BPMP_HOME/packages/<name>/versions/<v>/`. A warm cache short-
circuits the download.

## Constraints (SemVer subset)

| Spec       | Matches                                          |
| ---------- | ------------------------------------------------ |
| `*`        | any                                              |
| `0.1.0`    | exactly 0.1.0                                    |
| `^0.1.0`   | `>=0.1.0, <0.2.0` (0.x: minor bumps)             |
| `^1.2.0`   | `>=1.2.0, <2.0.0` (major fixed)                  |
| `~0.1.0`   | `>=0.1.0, <0.2.0`                                |
| `>=0.1.0`  | at least 0.1.0                                   |
| `feat`     | the literal moving `<version>-feat` tag          |
| `latest`   | highest non-prerelease tag                       |

Conflict between two packages → bpmp **reports both edges** and asks you to
pin the dep yourself in `requires` (first-fit resolver, no backtracking).

## Toolchain management

```bash
bpmp use botopink 0.0.2                       # exact version
bpmp use botopink latest                      # highest stable
bpmp use botopink dev --from /tmp/zig-out     # link a local zig-out (hackers)

bpmp self update                              # bump bpmp in-place
bpmp self update --toolchain                  # also bump active botopink
bpmp self uninstall --yes                     # remove $BPMP_HOME
```

`bpmp self update` swaps the running binary atomically on POSIX
(`rename($BPMP_HOME/bin/bpmp.new, $BPMP_HOME/bin/bpmp)`); on Windows a
deferred-swap helper completes on the next `bpmp` invocation.

## What `bpmp run` does

```bash
bpmp run -- build src/main.bp
```

is equivalent to:

```bash
BOTOPINK_LIB_ROOTS=$BPMP_HOME/packages/erika/versions/0.0.1:… \
    $BPMP_HOME/botopink/versions/stable/botopink build src/main.bp
```

with `PATH=$BPMP_HOME/bin:$PATH` exported so child processes still see
bpmp.

## Installing project deps from git (v0.beta.20)

A project may declare its lib dependencies in object form, with source
coordinates instead of bare names:

```json
{
  "name": "emilia-card",
  "version": "0.0.1",
  "target": "commonJS",
  "dependencies": {
    "jhonstart": {
      "git": "https://github.com/botopink/jhonstart.git",
      "branch": "feat"
    },
    "emilia": {
      "git": "https://github.com/botopink/emilia.git",
      "branch": "feat"
    }
  }
}
```

Run `bpmp install` from the project directory:

```bash
bpmp install
```

bpmp clones each entry into a host-wide content-addressed store under
`$BPMP_HOME/store/<name>/<full-rev>/` (default `~/.cache/bpmp/store/` via
XDG), symlinks them per-project under `<project>/.botopinkbuild/deps/<name>`,
and writes `botopink.lock` sibling to `botopink.json` pinning every dep
to its resolved 40-char commit SHA. Subsequent invocations reuse the
store entries (CAS hit) without re-cloning.

| Flag | Effect |
|---|---|
| `bpmp install <name>` | Install / refresh a single declared dep. |
| `bpmp install --update` | Re-resolve every branch tip; rewrite `botopink.lock`. |
| `bpmp install --frozen` | Refuse to clone; error with **DEP-004** if any dep is missing from the lockfile. CI mode. |
| `bpmp install --dry-run` | Print the planned actions (clone / reuse-cas / link-path / skip-legacy) without touching disk. |

`DepSpec` fields (one of `git`/`path` required):

| Field | Type | Meaning |
|---|---|---|
| `git` | string | Clone URL (HTTPS or SSH). Mandatory unless `path` is set. |
| `branch` | string | Track this branch; lockfile pins the tip-commit SHA. |
| `rev` | string | Pin this commit SHA (40 chars). Strongest pin. |
| `tag` | string | Pin this annotated tag. |
| `path` | string | Local source path (abs or relative to project). Symlinks instead of cloning. Mutually exclusive with `git`. |

Legacy `"dependencies": ["foo","bar"]` is still accepted (bare-name
resolver only — `bpmp install` is a no-op for these and the compiler
finds them through `libs/<name>/` / `BOTOPINK_LIB_ROOTS`).

Diagnostics:

| Code | Trigger |
|---|---|
| **DEP-001** | `dependencies` is neither array-of-strings nor object-of-DepSpec |
| **DEP-002** | A spec declares neither `git` nor `path` |
| **DEP-003** | A spec carries more than one of `branch`/`rev`/`tag` (warning; `rev > tag > branch`) |
| **DEP-004** | `--frozen` and a dep has no lockfile entry |
| **DEP-005** | Clone / network failure (the underlying `git` stderr is shown) |

## Troubleshooting

- `bpmp install` says `botopink.json not found` → you're not in a project.
  Run `bpmp init` first.
- `bpmp install` (no args) says `no botopink.lock.json` → for the legacy
  compiler-distribution flow, there's nothing to replay yet (add a dep with
  `bpmp install <name>`). For the v0.beta.20 install-from-deps flow this
  does not apply — `botopink.lock` is created the first time `bpmp install`
  runs against an object-form manifest.
- `botopink.lock.json: schema mismatch` → run `bpmp sync --update` to
  regenerate. bpmp does not auto-migrate.
- `bpmp run` says `no active botopink` → run `bpmp use botopink <ver>`
  first (or `bpmp use botopink dev --from <dir>` during compiler hacking).

See [examples.md](examples.md) for three worked scenarios.
